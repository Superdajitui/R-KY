## 部署备忘

- **仓库**：https://github.com/Superdajitui/R-KY （Public）
- **发布目录**：`main` 分支的 `/docs`
- **推送方式**：SSH over 443（`ssh://git@ssh.github.com:443/Superdajitui/R-KY.git`）
- **密钥**：`~/.ssh/id_ed25519_github`（换电脑要重新跑 `tools\设置SSH密钥.bat`）

> **为什么用 SSH 而不是 HTTPS？**
> 这台机器上装了 **Watt Toolkit（Steam++）**，它会把 `github.com` 劫持到
> `127.0.0.1` 做本地反代（hosts 里能看到一整列 `127.0.0.1 github.com`）。
> 它的中间人证书过不了 git 的 schannel 吊销检查，HTTPS 推送必然报
> `CRYPT_E_NO_REVOCATION_CHECK`。而 `ssh.github.com` 不在劫持列表里，
> 也不走 TLS，所以完全绕开了这个问题。

## 本地预览

**双击 `打开网站.bat`** —— 会自动起服务、列出手机可用的地址、检查防火墙，
然后打开浏览器。

```bash
npm start                # 监听所有网卡 → http://127.0.0.1:4321/
npm run preview:docs     # 预览打包产物，并模拟 GitHub Pages 的子路径
```

> **为什么要起服务，而不是直接双击 `index.html`？**
> 浏览器对 `file://` 协议下的自定义字体有 CORS 限制，直接双击打开时
> Anton / Inter 会被拦掉，标题会退化成系统字体（照片不受影响，能正常显示）。

## 在手机 / 平板上打开

同一 Wi-Fi 下的手机、平板可以直接访问，**不需要部署**。有两步：

### 1. 用启动器拿到地址

双击 `打开网站.bat`，它会打印形如 `http://192.168.0.107:4321/` 的地址。
在手机浏览器里输入这个地址即可。

> 服务默认监听 `0.0.0.0`。如果只绑 `127.0.0.1`（回环地址），
> 局域网里的手机根本连不上 —— 这是"其他设备打不开"最常见的原因。

### 2. 放行防火墙（只需做一次）

以管理员身份运行 `tools\放行防火墙.bat`，会自动弹出授权窗口并添加一条
TCP 4321 的入站放行规则。

> **为什么必须手动放行？** 如果你的网络被 Windows 识别为「公用网络」
> （`设置 → 网络和 Internet → 以太网 → 网络配置文件类型`），防火墙会阻止
> **一切**入站连接，而且**不会弹**"是否允许访问"的提示，所以只能手动加规则。
> 启动器会检测这条规则是否存在，缺失时会提醒你。

想撤销这条规则：

```powershell
netsh advfirewall firewall delete rule name="个人网站预览 4321"
```

### 排查清单

| 现象 | 原因 |
|---|---|
| 手机提示"无法访问此网站" | 防火墙规则没加，或没连同一个 Wi-Fi |
| 地址栏输入后跳到搜索引擎 | 漏了 `http://` 前缀 |
| 电脑上能开、手机上不行 | 服务绑到了 `127.0.0.1` 而不是 `0.0.0.0` |
| 想在外面（4G/5G）也能看 | 局域网方案做不到，需要部署到公网 |

## 换照片

素材已经用 `tools/cutout.mjs` 抠好背景（白底 → 透明）。
换一张新证件照后重新跑一遍即可：

```bash
npm run cutout
```

这个脚本做了几件事：

1. **自动判定背景色** —— 在四条边框带里挑颜色最均匀的一条作为背景参考色。
   不能四边取平均，否则底部的深色衣服会把背景色带偏成灰色（这个坑踩过）。
2. **区域生长泛洪** —— 只吃掉与画面边缘连通的背景，所以脸部高光、
   白衣服上的白点不会被误伤成透明洞。
3. **饱和度守卫** —— 背景必须是"灰/白"的低饱和像素。
   只靠颜色距离是不够的：头发与耳朵交界处的抗锯齿渐变同样满足"距离够近"，
   泛洪会顺着这条渐变啃进耳朵，表现为耳朵被咬掉一块锯齿状缺口（这个坑也踩过）。
   白底饱和度是 0，皮肤是 20+，饱和度才是可靠的判据。
   容许上限 = 背景自身饱和度 + 0.09，所以彩色背景也能自适应。
4. **形态学开运算** —— 对背景掩膜做「先腐蚀后膨胀」，清掉仍然渗进主体的背景细缝。
5. **只在边界 3px 内羽化**，主体内部锁死 `alpha=1`。这一步很关键：
   如果主体也按"到背景色的距离"算半透明，去白边的除法会把肤色算成橘色。
6. **unmultiply 去白边** —— 避免深色背景上出现一圈白色描边。
7. **底部渐隐烤进 alpha 通道** —— 让肩膀溶进黑底。
   不用 CSS `mask-image` 是因为 mask + filter + mix-blend-mode 叠在同一个元素上时，
   个别浏览器/驱动组合会把整块渲染成空白。
8. 自动裁掉透明边距，并额外生成一个**霓虹绿双色调版本**（鼠标悬停人物时叠加）。

### 抠图质检

## 设计说明

**双色系统**（来自 Lando 官网）：绝对黑 `#111112` + 霓虹绿 `#D2FF00`，
没有第三种颜色。想换主色只改 `style.css` 里的 `--neon`。

**首屏纵深**：`KERRY` 在人物之后，`任恺昱` 在人物之前，形成前后夹层的海报感。
实现上依赖 `.hero__title` **不设 `z-index`** —— 一旦设了就会创建层叠上下文，
把两个字一起锁在人物下面。（详见 `style.css` 里的注释。）

**首屏位置微调**：改 `:root` 里这几个变量就能整体挪动构图：

```css
--hero-name-top:15svh;        /* KERRY 距顶部 */
--hero-name-bottom:28px;      /* 任恺昱 距底部 */
--hero-portrait-h:...;        /* 人物高度 */
--hero-portrait-bottom:0;     /* 人物距底部 */
```

### 「任恺昱」的字号为什么是这个式子

```css
font-size: max(2rem, min(calc(21.2svh - 44px), 174px));
```

不是随手写的，是被**衣领**约束出来的：

1. `tools/find-collar.mjs` 沿人物中轴扫亮度剖面，量出衣领在图高 **70.5%** 处
   → 胸口可用高度只有人物高度的 **29.5%**
2. 人物高度是 `min(72svh, 740px)`，所以胸口空间 = `min(21.2svh, 218px)`
3. 减去上下留白 44px，就是字号上限

**两个坑**：

- 字号**不能按 `vw` 定** —— 宽屏上人物高度被封顶，名字却还在涨，会撑爆胸口。
- 也**不能只按 `svh`** —— 人物一旦到 740px 封顶，视口再高胸口也不会变高，
  字号却继续涨。实测 1024×1366 那档就是这样只差 6px。
  所以 `bottom` 也从 `svh` 改成了固定 `28px`。

改完务必跑一遍验证，它会量出**墨迹真正的顶端**（不是盒子顶端 ——
CJK 字形在 em 盒里有上留白，用盒子算会误判）：

```bash
npm run test:collar      # 单档检查
npm run collar           # 重新量衣领位置
```

实测七档尺寸（1024×1366 / 1180×820 / 1366×768 / 1440×900 /
1920×1080 / 2560×1440 / 820×1180）间距稳定在 15~16px。

**渐进增强**：所有入场动效都挂在 `html.js` 下。脚本被禁用或加载失败时，
`<noscript>` 会兜底显示全部内容 —— 不会出现"整站空白"。

**无障碍**：完整支持 `prefers-reduced-motion`，键盘焦点有可见描边，
`alt` 文本、语义化标签、`aria` 属性齐备。

## 开场页（欢迎页）

打开网站先看到一整片主题色 + 「欢迎来到我的个人网站」，下滑后主页从下方滑上来盖住它。

**实现方式**：欢迎页是 `position: fixed` 铺满视口，主页前面放了一个
`.welcome-spacer` 占位块（一整屏高）把它顶下去。于是"主页滑上来"这件事
**完全由滚动位置驱动，不需要 JS 做位移** —— 即使脚本出问题，
页面依然能正常滚动阅读，只是少了视差那点动画。

几个关键点：

| 位置 | 说明 |
|---|---|
| `.welcome-spacer` | 一整屏高的占位块。用独立元素而不是给 `main` 加 `margin-top` —— margin 会和 `body` 折叠，可能把整页推下去留出空隙 |
| `main` / `.foot` | 都必须 `z-index:2` 抬到欢迎页（`z-index:1`）之上，否则滚到底部时页脚会被欢迎页盖住 |
| `body.is-ready` | 触发**欢迎页**的文字揭示（遮罩逐行上推） |
| `body.is-hero` | 触发**首屏**的入场动画。用 `is-hero` 而不是 `is-ready` —— 首屏一开始被盖着，用 `is-ready` 的话动画会在背后空放，滑上来时已经静止了 |
| `body.at-welcome` | 欢迎页期间收起导航和进度条，保持开场干净 |

滚回顶部还能再看到欢迎页（`fixed` 元素保留在 DOM 里，不销毁）。

**交互**：点欢迎页任意位置都能下滑进入主页；键盘用户走页脚那个
`<a href="#hero">`。

## 字体

全部自托管，运行时不依赖任何外部字体服务。

| 字体 | 用途 | 大小 |
|---|---|---|
| Inter | 拉丁字母、数字 | 6 个字重，共 141 KB |
| Anton | 超大英文标题、数字 | 18 KB |
| **Noto Sans SC（子集）** | **中文** | **158 KB** |

### 为什么中文也必须自托管

原来的中文字栈是 `'Inter','Microsoft YaHei','PingFang SC',system-ui`：

- **Windows** 命中微软雅黑
- **iPhone** 命中苹方
- **安卓** 前两个都没有，回退到思源黑体

三个平台字形本来就不同 —— 同一个「镂空描边」效果在手机上会和电脑上对不上。
把中文字体也自托管，才能保证所有设备渲染一致。

### 子集是怎么做的

完整思源黑体有 5 MB 多，而本站一共只用了 **568 个汉字**。
用 Google Fonts 的 `text=` 参数可以拿到**只含指定字符的可变字体**
（一个字重文件覆盖 400~900），压到 158 KB。

```bash
node tools/extract-chars.mjs     # 扫描页面，提取用到的字符 → tools/charset.txt
node tools/build-cjk-font.mjs    # 按字符集生成子集 → assets/fonts/
# 等价于 npm run font:chars / npm run font:build
```

> ⚠️ **加了新文案之后要重跑这两个脚本**，否则新出现的汉字不在子集里，
> 会回退到系统字体，字形又和其他字对不上。
> `test:welcome` 里有一条检查会盯着「中文是否全部走自托管字体」。

### 镂空描边的三个坑

`.welcome__line--outline` 的做法是「描边 + 一层同字填充盖住内半部分」。
看起来简单，实际连着踩了三次：

**① 不能填 `transparent`（常规写法）。**
思源黑体是**由重叠笔画拼合**的，填透明的话每个笔画的轮廓都会画出来，
字内部出现一道道交叉线（"我""的""网"尤其明显）。

**② 不能用 `paint-order:stroke fill`。**
它能盖住交叉线，但**移动端不可靠** —— 微信/QQ 这类内置浏览器实测完全不生效；
而且它会连描边的**内半部分**一起盖掉，桌面上 2px 描边凭空变成 1px。
两个现象同时出现，正好对上「手机没变化、电脑变细了」。

**③ 换 `::after` 叠层，但要记得写描边颜色。**

```css
.welcome__line--outline > span{
  position:relative;
  color:transparent;
  -webkit-text-stroke:clamp(3px, 0.028em, 4.4px) var(--ink);  /* 颜色不能省！ */
}
.welcome__line--outline > span::after{
  content:attr(data-text);       /* HTML 上要写 data-text，叠加层靠它取原文 */
  position:absolute;left:0;top:0;
  color:var(--neon);             /* 填背景色，盖住交叉线和描边内半 */
  -webkit-text-stroke:0;
}
```

`-webkit-text-stroke` 是**简写属性**，只给宽度的话颜色取 `currentColor`，
而这里 `color` 是 `transparent` —— **描边会整个消失，页面看着还挺正常**。
这个 bug 肉眼没发现，是靠数渲染出来的深色像素才抓到的。

**宽度写的是目标值的两倍**（内半被填充盖住，外半才是最终看到的）。
用 `em` 而不是 `px`：写死 px 的话，手机上 4px 配 47px 的字显得笨重，
桌面上 4px 配 152px 又偏精致，同一个设计在两种尺寸下观感对不上。

**这招对首屏的「任恺昱」也适用** —— 关键是加了衣领约束之后，
名字已经**完全落在 T 恤上**，不会盖到脖子或脸。
T 恤那块布料实测标准差只有 3~5（`tools/sample-shirt.mjs`），够均匀，
所以直接用取到的平均色 `rgb(42,46,49)` 填充，边界看不出来。

```css
.hero__cn{
  --shirt:rgb(42,46,49);        /* T 恤实测平均色，换照片要重新量 */
  color:transparent;
  -webkit-text-stroke:4px var(--neon);   /* 外显 2px */
}
.hero__cn::after{
  content:attr(data-text);
  position:absolute;left:0;top:0;
  color:var(--shirt);           /* 填衣服色，盖住内部交叉线 */
  -webkit-text-stroke:0;
}
```

`npm run test:hero` 里有 6 条检查盯着：填充层是否存在、填充色是否等于
`--shirt`、描边颜色、以及**名字区域的实际霓虹占比**
（过低 = 描边没画出来；过高 = 内部交叉线露出来了）。

`npm run test:welcome` 里有 6 条检查盯着这块：描边宽度、描边颜色、
填充层是否存在、以及**镂空区域的实际墨量**（只有描边 → 个位数百分比；
填充层丢了会明显变高；描边丢了会变成 0）。

## 验证脚本（开发用，可删）

```bash
npm run shot           # 截图各版块到 tools/shots/（含开场页、手机、平板横竖屏）
npm run inspect        # 量首屏元素实际位置，检查是否压盖 / 溢出视口
npm run test:welcome   # ★ 开场页 → 主页 的完整流程（滚动、点击、滚回顶部）
npm run test:hero      # ★ 首屏照片回归：必须显示出来，且脸上不能被绿光糊住
npm run test:subpath   # ★ 在 /R-KY/ 子路径下实测生产包，部署前必跑
npm run verify:live    # 线上站点完整验证
npm run peek:live      # 只截线上首屏看一眼，排查「线上到底长什么样」
```

**`test:welcome`** 分四个阶段：加载完停在欢迎页（铺满、主题色、文案完整、
首屏还在折叠线以下）→ 下滑揭幕（半途抓帧验证幕布效果 + 视差）→
滚回顶部还能看到欢迎页 → 点击也能进入。

**`test:hero`** 守着两件容易出错的事，都真的抓出过 bug：

- **照片必须显示出来。** 曾经 WebGL 初始化成功就隐藏静态图，
  结果 canvas 画不出内容时照片"凭空消失"。
- **脸上不能被绿光糊住。** `.hero__halo` 是定位元素，`<picture>` 是静态定位，
  绘制顺序里 halo 反而在上。检查方式是**直接比对页面渲染出来的脸颊颜色
  和源图的颜色** —— 层级一错，数值立刻偏离（正常偏差 < 1，出错时 34）。

写这条检查时还踩了个 sharp 的坑：**`stats()` 只统计输入图，会忽略 `extract`**。
写成 `sharp(src).extract(box).stats()` 拿到的是整图统计，
换任何取样框结果都一样。必须先 `toBuffer()` 落地。

**`test:subpath` 是部署前的关键一步。** GitHub Pages 的项目站点跑在
`/仓库名/` 子路径下，而不是域名根目录。任何一处写成 `/assets/...` 的绝对路径
都会 404，**而这个问题在本地根路径预览时完全看不出来** —— 要等部署完
打开网页发现白屏才知道。这个脚本会：

- 以 `--prefix=/R-KY` 启动服务器，真实模拟子路径环境
- 检查首页的每个资源、照片、字体是否加载成功
- 检查 404 页的样式和「回到首页」链接是否指向正确位置

实测它抓出过一个真 bug：404 页用相对路径引用样式表，在
`/R-KY/任意路径/` 下会被解析成 `/R-KY/任意路径/assets/...` 直接 404，
整页样式全丢。现在由打包脚本注入 `<base href="/R-KY/">` 解决了。

## 踩过的坑（改代码前先看一眼）

1. **`.hero__title` 不能设 `z-index`** —— 一设就创建层叠上下文，把「KERRY」和
   「任恺昱」一起锁在人物之下，前后夹层的纵深效果直接失效。
2. **批处理文件里不要写中文** —— cmd.exe 按字节偏移读 .bat，多字节字符可能被
   切在中间，导致后续命令行错乱（实测会报 `'手机' is not recognized`）。
   所以 `.bat` 全是纯 ASCII 跳板，中文逻辑放在 `tools\*.ps1` 里，
   且 .ps1 必须存成 **UTF-8 with BOM**，否则 Windows PowerShell 5.1 会读成乱码。
3. **不要给 `.hero__portrait` 叠加 mask + filter + mix-blend-mode** ——
   个别浏览器/驱动组合会把整块渲染成空白，症状就是"照片完全显示不出来"。
   底部渐隐已经烤进图片 alpha 通道。
4. **`svh` 要有 `vh` 兜底** —— 不支持 `svh` 时会让整个 `min()` 失效，
   绝对定位的人物尺寸会失控。
5. **404 页的资源路径必须相对站点根** —— 见上面 `test:subpath` 的说明。
6. **抠图不能只看颜色距离** —— 头发与耳朵交界的抗锯齿渐变同样"距离够近"，
   泛洪会顺着它啃进耳朵。必须加饱和度守卫，详见 `tools/cutout.mjs`。
7. **这台机器的 `github.com` 被 Watt Toolkit 劫持到 `127.0.0.1`** ——
   所以 git 必须走 SSH（见上面的部署备忘）。另外 `github.io` 也在劫持列表里，
   意味着**你自己浏览器访问自己的网站会经过 Watt Toolkit 代理**；
   如果你关掉 Watt Toolkit，记得确认 `github.io` 还能正常解析。
8. **插值进 GLSL 的数字必须是浮点字面量** —— JS 会把 `14.0` 渲染成 `"14"`，
   而 GLSL ES 里 `vec2 * int` 非法，着色器直接编译失败。用 `toFixed()` 生成。
9. **下载的素材可能本来就是透明底** —— 这时"自动识别背景色"会把边界上的
   透明像素读成 `rgb(0,0,0)`，然后泛洪顺着黑色把主体暗部整个啃掉。
   `cutout.mjs` 现在会先检查边界透明度，是透明图就直接拒绝运行。
10. **sharp 的 `resize` 先于 `composite` 执行** —— 写成
    `.composite(x).resize(700)` 会先缩到 700 宽再把大图贴上去，
    直接报尺寸不匹配。必须分两步。
11. **sharp 的 `composite` 不允许叠加层大于底图** —— 给旋转留白时要注意，
    留过头（比如 40%）叠加层就会超过底图尺寸而报错。
12. **同一进程内反复写同一个路径会撞 `EBUSY`** —— 批量生成变体时，
    让每个变体写各自的文件名。
13. **静态定位的元素会被"定位元素 + z-index:0"盖住** ——
    `.hero__halo`（光晕）是定位元素，`<picture>` 是静态定位，
    绘制顺序里 halo 反而在上，结果绿光糊在脸上。
    给 `picture` 加 `position:relative; z-index:1` 才压得住。
14. **`sharp().stats()` 只统计输入图，会忽略 `extract`** ——
    写成 `sharp(src).extract(box).stats()` 得到的是**整图**统计，
    换任何取样框结果都一样（当时五个完全不同的框返回了同一组数值，
    极具迷惑性）。必须先 `toBuffer()` 落地再统计。
15. **puppeteer 的 `screenshot({clip})` 用文档坐标，不是视口坐标** ——
    `getBoundingClientRect()` 给的是视口坐标，两者差一个滚动偏移。
    加了开场页之后首屏被推到第二屏，裁剪框整块偏到空白区
    （量出来亮度 18，正好是背景色）。必须 `r.top + window.scrollY`。
16. **给 `main` 加 `margin-top` 做整屏偏移不可靠** ——
    margin 会和 `body` 折叠，可能把整个页面推下去。用独立的占位元素更稳。
17. **固定的全屏元素会盖住后面的静态内容** ——
    欢迎页 `z-index:1`，`main` 和 `.foot` 都得抬到 `z-index:2`，
    否则滚到底部时页脚会被盖住。这个只有滚到底才会发现。

## 技术栈

纯手写 **HTML + CSS + JavaScript**，运行时**零依赖、零构建步骤**。
`node_modules` 只在开发和重新生成素材时用到，部署时整个 `tools/` 和
`node_modules/` 都可以不要，只传 `index.html` + `assets/` 即可。
